# Ovo documentation

Everything that explains the design, from the first decisions to the print plan. Start with the
[design brief](design-brief.md), then read the notes in the order the design was done: blade,
hardware, layout, CAD, print plan. The [technical report](report/ovo-report.pdf) condenses all of
it into one document. Back to the [project README](../README.md).

Every performance number in these documents is a model estimate: Ovo v1 is a display build that has
not been printed or tested in water yet.

## Design brief

| document | what it holds |
|---|---|
| [design-brief.md](design-brief.md) | scope, the decisions taken with the owner (2026-10-03 and 2026-10-05), the engineering decisions behind the concept (downstream rotor folding forward, pre-cone from the hull, equator joint, roll fins, detents) and what is out of scope for v1 |

## Technical report (`report/`)

[report/ovo-report.pdf](report/ovo-report.pdf) is the compiled report and `report/ovo-report.typ`
its source. `scripts/report.py` (`make report`) writes the generated parts and compiles it with the
typst Python package: `report/data.typ` (every number, extracted from the JSON files above; do not
edit), `report/refs.bib` (bibliography), `report/figures/` (the report's own drawings) and
`report/img/` (compressed copies of the renders).

## Where the numbers come from

```
ovo/params.py  +  data/*.json            single source of truth: every dimension, the study tables
        |                                (blade_design, hardware, bom, layout, layout_rotor, layout_internal)
        v
ovo/cad/*.py  ->  out/cad/checks/*.json  measured on the CAD at every build (scripts/build.py):
        |                                B-rep part audit, interference and clearances on fine meshes
        |
        v
notes, report, README, site              quote those files; the report generates its numbers from them
```

`data/` holds the design-study outputs (committed, regenerated by `ovo.bem`, `ovo.layout` and
`ovo.layout_internal`); `out/` holds the build outputs (git-ignored, rebuilt by `make build` and
published by the CI workflow).
